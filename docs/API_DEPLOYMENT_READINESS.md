# Boatswain API deployment readiness

This document prepares the API for a controlled Render deployment. **No Render service or database has been created by this change.** The draft Blueprint keeps auto-deploy disabled.

## Blueprint resources

- Node.js API web service: `boatswain-property-api`
- PostgreSQL database: `boatswain-property-db`
- Health check: `/ready`
- Migrations run on service start with `prisma migrate deploy`
- Auto-deploy: disabled until the release is approved

The current Blueprint uses Render's free plans as a low-cost staging baseline. Free instances may spin down and are not an appropriate uptime guarantee for a live property transaction service. Select a production service/database plan and backup policy before launch.

## Required environment values

| Variable | How to set it | Purpose |
| --- | --- | --- |
| `DATABASE_URL` | Render database connection reference | PostgreSQL connection |
| `JWT_SECRET` | Generated by Render | Signing customer sessions |
| `CORS_ORIGIN` | Explicit comma-separated HTTPS origins | Allow only the approved Boatswain web origins |
| `PASSWORD_RESET_URL` | HTTPS customer website URL | Password-reset link destination |
| `SMTP_HOST` | Email provider SMTP host | Outbound customer email |
| `SMTP_PORT` | Default 587; change only if provider requires | SMTP port |
| `SMTP_SECURE` | Default false for STARTTLS on 587; true for implicit TLS on 465 | SMTP transport mode |
| `SMTP_USER` | Email provider credential | SMTP authentication |
| `SMTP_PASSWORD` | Secret from email provider | SMTP authentication |
| `SMTP_FROM` | Approved sender name and address | Customer-facing sender |

Never place SMTP credentials or JWT secrets in GitHub files, browser code or chat. Enter them directly into the hosting provider's protected environment settings.

## Password recovery activation

1. Choose and verify an email provider and an authenticated sender address.
2. Configure all SMTP environment values in Render.
3. Set `PASSWORD_RESET_URL` to the actual HTTPS URL where the Boatswain account modal is deployed.
4. Confirm the deployed frontend has its API URL configured and its reset-link route reads the `passwordResetToken` URL fragment.
5. Send a controlled test to a company-owned mailbox, confirm the link expires after 30 minutes, confirm it works once, and verify all prior sessions are revoked.
6. Check delivery, bounce and failure monitoring before enabling customer self-service.

Until SMTP is configured, password-reset requests intentionally return a generic response and do not reveal whether an email address exists; no reset email can be delivered.

## Pre-deployment gates

- Confirm the final API origin and approved CORS origins.
- Confirm the company email provider and sender identity.
- Confirm the final customer website URL and official group/property domain.
- Confirm the database retention, backups and restore procedure.
- Provision the first administrator using the documented one-time CLI procedure; do not add a public admin-registration route.
- Apply migrations to a staging database first and test rollback/restore.
- Run API, Chromium, account recovery, reservation concurrency and payment-ledger tests against the deployed staging API.
- Keep payment collection disabled until a provider, merchant account, signed webhook verification, reconciliation and approved legal terms are in place.

## Release safety

The Render Blueprint is a proposal only. Do not create or upgrade services, connect a payment provider, enable auto-deploy, or merge PR #1 without explicit release approval.
